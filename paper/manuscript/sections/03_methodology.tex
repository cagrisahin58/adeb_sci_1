\section{Methodology}
\label{sec:methodology}

Figure~\ref{fig:study_overview} summarizes the design. Two architectures are trained under one matched adversarial recipe with three independent runs each, and every evaluation is logged per sample on the full test set, so that, within each analysis, the four conditioning protocols of Section~\ref{subsec:metrics} can be applied to the same records without re-running the attack. The subsections below fix the threat model, the models, the attacks and the training protocol in that order, and then define the measurements.

% 3.1 Threat Model
% ----------------------------------------------------------------------------
\subsection{Threat Model}
\label{subsec:threat_model}

We consider the standard $\Linf$ threat model where an adversary can perturb input images within a bounded region:
\begin{equation}
    \mathcal{B}_\eps(x) = \{x' : \|x' - x\|_\infty \leq \eps\}
\end{equation}

Following established conventions for CIFAR-10~\cite{krizhevsky2009learning, croce2021robustbench}, we use $\eps = 8/255 \approx 0.031$ as the primary perturbation budget, with additional full-test PGD-10 evaluations at $\eps \in \{2/255, 4/255, 16/255\}$ for the epsilon sweep analysis.

We evaluate under both white-box (full model access) and black-box (transfer attack) scenarios. For white-box attacks, the adversary has complete knowledge of model architecture and parameters. For transfer attacks, adversarial examples are generated on a source model and evaluated on a different target model.

% ----------------------------------------------------------------------------
% 3.2 Model Architectures
% ----------------------------------------------------------------------------
\subsection{Model Architectures}
\label{subsec:architectures}

\paragraph{CNN Models}

\textbf{ResNet-18}~\cite{he2016deep}: A widely used baseline CNN with residual connections, containing 11.2M parameters. We use the standard architecture designed for CIFAR-10 (initial 3$\times$3 convolution instead of 7$\times$7).

\textbf{WideResNet-28-10}~\cite{zagoruyko2016wide}: A wider variant of ResNet with 36.5M parameters, commonly used as a reference architecture for adversarial robustness on CIFAR-10. We use the pretrained robust checkpoint of Gowal et al.~\cite{gowal2020uncovering} distributed via RobustBench~\cite{croce2021robustbench}. This model was trained with additional unlabeled data and a stronger recipe than our standard adversarial training, so it serves as a reference point rather than a matched comparison.

\paragraph{Vision Transformer Models}

\textbf{ViT-Tiny}: We use the ViT-Tiny architecture from the \texttt{timm} library~\cite{rw2019timm}, adapted for CIFAR-10 by bilinearly upsampling inputs to 224$\times$224. The architecture uses 16$\times$16 patches (196 patches per image), 192-dimensional embeddings, 12 transformer blocks with 3 attention heads each, MLP ratio of 4, and totals 5.7M parameters. The model is trained \emph{from scratch} on CIFAR-10 (no ImageNet pretraining) with basic augmentation (random crop and horizontal flip), then adversarially fine-tuned. Since ViT robustness on small datasets is known to be sensitive to the training recipe~\cite{debenedetti2023light, mo2022adversarial}, our architecture-level conclusions should be interpreted as holding \emph{under this baseline training recipe} and not for optimally trained ViTs.

% ----------------------------------------------------------------------------
% 3.3 Attack Methods
% ----------------------------------------------------------------------------
\subsection{Attack Methods}
\label{subsec:attack_methods}

\paragraph{FGSM}
Single-step attack with step size equal to the perturbation budget:
\begin{equation}
    x_{adv} = x + \eps \cdot \text{sign}(\nabla_x \mathcal{L}_{CE}(f(x), y))
\end{equation}

\paragraph{PGD}
Iterative attack with step size $\alpha = 2/255$ and random initialization:
\begin{equation}
    x^{t+1} = \Pi_{\mathcal{B}_\eps(x)} \left( x^t + \alpha \cdot \text{sign}(\nabla_{x^t} \mathcal{L}_{CE}(f(x^t), y)) \right)
\end{equation}
with $x^0 = x + \mathcal{U}(-\eps, \eps)$. We use PGD-10 (10 iterations) for both adversarial training and evaluation throughout this work (Table~\ref{tab:main_results}).

\paragraph{AutoAttack}
We use AutoAttack~\cite{croce2020reliable}, the standardized ensemble attack combining APGD-CE (Auto-PGD with cross-entropy loss), APGD-T (Auto-PGD with targeted DLR loss), FAB-T (targeted Fast Adaptive Boundary attack), and Square Attack (score-based black-box attack).

% ----------------------------------------------------------------------------
% 3.4 Defense Methods
% ----------------------------------------------------------------------------
\subsection{Defense Methods}
\label{subsec:defense_methods}

\paragraph{Adversarial Training (AT)}
We employ a mixed adversarial training objective that combines clean and adversarial losses:
\begin{equation}
    \mathcal{L} = (1 - \lambda)\,\mathcal{L}_{CE}(f_\theta(x), y) + \lambda\,\mathcal{L}_{CE}(f_\theta(x_{adv}), y)
\end{equation}
where $\lambda = 0.5$ balances standard classification performance with adversarial robustness. The inner maximization generates adversarial examples using PGD-10 ($\alpha = 2/255$, $\eps = 8/255$), computed with the model in training mode so that attack generation and the parameter update see consistent batch-normalization statistics, as in the reference implementation of Rice et al.~\cite{rice2020overfitting}. Mixing the two losses helps maintain clean accuracy while building robustness, since training solely on adversarial examples can degrade natural performance. While alternative formulations such as TRADES~\cite{zhang2019theoretically} offer theoretically grounded trade-off mechanisms, this work focuses on standard adversarial training to isolate architectural effects from defense-specific interactions.

% 3.5 Training Protocol
% ----------------------------------------------------------------------------
\subsection{Training Protocol}
\label{subsec:training}

\paragraph{Clean Training}
For CNNs, we use SGD optimizer with initial learning rate 0.1, cosine annealing schedule~\cite{loshchilov2016sgdr}, weight decay $5 \times 10^{-4}$, and 200 epochs. For ViTs, we use AdamW optimizer~\cite{loshchilov2017decoupled} with initial learning rate $10^{-3}$, cosine annealing, weight decay 0.05, and 200 epochs.

\paragraph{Adversarial Training}
Starting from our clean-trained checkpoints, we fine-tune with reduced learning rates: CNNs use SGD with LR $10^{-3}$ and cosine annealing for up to 100 epochs, while ViTs use AdamW with the same learning rate and schedule. Gradients are clipped to a global $L_2$ norm of 10, and batches with non-finite loss are skipped. Data augmentation includes random cropping with 4-pixel padding and horizontal flipping; all models consume raw pixel inputs in $[0,1]$ without mean/std normalization, and attacks and epsilon budgets operate directly in this pixel space. The training batch size is 128 for the CNN and 64 for the ViT (evaluation batch sizes vary by analysis). Early stopping uses patience 20 with a 0.1 percentage-point improvement threshold.

\paragraph{Validation Split and Repetitions}
Model selection and early stopping use PGD-10 adversarial accuracy on a fixed 2{,}000-sample validation split. The split is drawn once (seed 777, indices stored with the code) and is shared by every model in the study, and it is excluded from the training set of \emph{both} the clean and the adversarial stage, so no checkpoint is ever selected on data it was trained on. The test set is touched only by the final post-hoc evaluations. We repeat the full pipeline, clean pre-training followed by adversarial fine-tuning, three times per architecture with independent seeds (1001 to 1003 for ResNet-18, 2001 to 2003 for ViT-Tiny), and pair the runs by index so that every cross-architecture comparison is between models trained under the same repetition. All tables report the mean and standard deviation over these three runs.

For one comparison in Section~\ref{subsec:robustness} we also refer to an earlier pair of checkpoints trained before this protocol was adopted, whose validation split had been part of clean pre-training. They enter only as a contrast: the difference between the two checkpoint sets is itself evidence about how far a single-run conclusion can move.

\subsection{Evaluation Metrics}
\label{subsec:metrics}

\paragraph{Robustness Metrics}
We evaluate models using three standard metrics: clean accuracy (classification performance on unperturbed test images), robust accuracy (classification performance on adversarial examples), and attack success rate (fraction of correctly classified clean images that become misclassified after attack). For white-box evaluations we additionally report the \emph{conditioned fooling rate}, the fraction of clean-correct samples that the attack flips, and its complement, conditioned survival. Because both PGD and AutoAttack count clean-misclassified samples as non-robust in our per-sample logs, absolute robust accuracy factorizes exactly as $\text{robust} = \text{clean} \times \text{conditioned survival}$, which lets us decompose robustness differences into a clean-accuracy component and a conditional-susceptibility component. Accuracies are also reported on the \emph{both-correct} subset (samples that both compared models classify correctly on clean inputs), which yields an exactly paired comparison on a shared sample set.

\paragraph{Transfer Attack Metrics}
Our transfer metrics are a family of \emph{conditioned fooling rates} that differ only in the conditioning set. The base member is the \emph{target-correct} rate: among the samples that the target model classifies correctly on clean inputs, the fraction that becomes misclassified under adversarial examples crafted on the source model. Given adversarial examples $\{x_{adv}^S\}$ generated against source model $f_S$, the conditioned transfer rate to target model $f_T$ is:
\begin{equation}
    T_c(f_S \rightarrow f_T) = \frac{\sum_{i=1}^{n} \mathbf{1}[f_T(x_i) = y_i]\,\mathbf{1}[f_T(x_{adv,i}^S) \neq y_i]}{\sum_{i=1}^{n} \mathbf{1}[f_T(x_i) = y_i]}
\end{equation}
Conditioning transfer evaluation on correctly classified samples is established practice, usually on the samples that every model in the study classifies correctly~\cite{liu2017delving, dong2018boosting, mahmood2021robustness, ravikumar2023trend, zhao2025revisiting}; the target-correct rate is the one-sided relaxation of that pool, and conditioning matters most in cross-architecture comparisons: the raw misclassification rate $\frac{1}{n} \sum_{i} \mathbf{1}[f_T(x_{adv,i}^S) \neq y_i]$ includes the target's clean error, so a target with lower clean accuracy appears more ``vulnerable'' to transfer even when no additional samples are flipped by the attack. We report the raw rate as a secondary metric for transparency and to quantify the size of this confound. Because the conditioning set itself is a protocol choice, we additionally report two alternatives: the \emph{both-correct} protocol, which conditions on samples that both the source and the target classify correctly~\cite{mahmood2021robustness, ravikumar2023trend}, and the \emph{successful-source} protocol, which conditions on target-correct samples whose attack succeeded on the source in the white-box sense. Both are established. The successful-source rate is the transferability metric of Ravikumar et al.~\cite{ravikumar2023trend}, whose Equation~(1) divides the number of examples that transfer to the target by the number generated against the source, over a pool restricted to samples both models classify correctly; it is also the protocol implied whenever a transfer rate is reported over ``successful'' adversarial examples. For directional claims we take the both-correct rate as the primary estimate, because it scores both directions on identical samples and therefore supports paired inference; the other three are reported beside it throughout. As Section~\ref{subsec:transfer} shows, these protocols can yield qualitatively different asymmetry conclusions, which is why every transfer number in this paper is given together with its protocol. Transfer rates are computed on the full test set (10{,}000 samples) with per-sample outcomes logged, and we report 95\% confidence intervals obtained by percentile bootstrap over samples (10{,}000 resamples).

\paragraph{Gradient Analysis Metrics}
We analyze gradient properties through three complementary metric families, computing gradients of per-sample losses so that magnitudes are independent of the evaluation batch size. Gradient norm ($\|\nabla_x \mathcal{L}\|_2$ and $\|\nabla_x \mathcal{L}\|_\infty$) measures overall sensitivity magnitude. Gradient sparsity is quantified with scale-invariant measures: Hoyer sparsity, the Gini coefficient of $|g|$, and the fraction of components below 1\% of the per-sample maximum, since fixed absolute thresholds conflate gradient scale with structure; Hoyer and Gini satisfy the scale-invariance axioms formalized by Hurley and Rickard~\cite{hurley2009comparing}. Gradient alignment measures the average pairwise absolute cosine similarity across samples (computed over all pairs of the 500 analysis samples):
\begin{equation}
    \text{Alignment} = \frac{1}{N(N-1)} \sum_{i \neq j} \left| \frac{\nabla_{x_i} \mathcal{L} \cdot \nabla_{x_j} \mathcal{L}}{\|\nabla_{x_i} \mathcal{L}\| \|\nabla_{x_j} \mathcal{L}\|} \right|
\end{equation}
We use the absolute cosine because shared sensitivity \emph{axes} matter for attack geometry regardless of sign; since sign coherence is what universal-perturbation arguments additionally require, we also report the signed mean cosine, which turns out to be near zero for every model (Section~\ref{subsec:gradient}). High absolute alignment indicates similar perturbation axes across inputs.

\paragraph{Spatial Locality Metrics}
Sparsity measures how many gradient components are large but says nothing about where they lie in the image, so we measure spatial structure separately on the channel-summed energy map $e = \sum_c (\nabla_x \mathcal{L})_c^2$, normalized to sum to one. We report the smallest pixel fraction whose energy sums to 50\% and to 90\% (smaller means more localized), the Shannon entropy of $e$ viewed as a distribution over pixels (lower means more localized), and Moran's $I$ with 4-neighborhood weights, which is positive when energy clusters in adjacent pixels. All four are invariant to the scale of the gradient, and all are computed per sample so that the two architectures can be compared with paired tests on identical inputs.

\paragraph{Token Aggregation for Layer-wise Analysis}
A transformer block emits one vector per token, so summarizing a block requires a choice. We report three: the CLS token alone, the mean over the 196 patch tokens, and the concatenation of all tokens flattened per sample. For the CNN each residual block output is flattened over its spatial dimensions. We report all three for the ViT because, as Section~\ref{subsec:attention} shows, they give different drift magnitudes and place the minimum at different depths.

\paragraph{Attention Metrics}
For the ViT we extract the post-softmax CLS-to-patch attention row of each block, averaged over heads. We report its Shannon entropy, which measures how broadly attention is spread, and its displacement under attack, measured as the total variation distance between the clean and adversarial attention distributions (bounded by 1). Both are computed per sample and averaged, on $n=1000$ samples per run.

\paragraph{ViT-Specific Transfer Attack}
To test whether the transfer results depend on using architecture-agnostic attacks, we additionally generate source examples with Token Gradient Regularization (TGR)~\cite{zhang2023tgr}, which zeroes the extreme-valued entries of the token-gradient tensors in the attention, QKV, and MLP paths during backpropagation and scales the remaining gradient by $\gamma=0.5$. Our implementation adapts the method to our CIFAR-10 ViT wrapper and to the budget used throughout this paper ($\eps=8/255$, $\alpha=2/255$, 10 steps, momentum 1.0) instead of the original ImageNet defaults. Because the result it produces is negative, two further details of our version matter. We apply a single $\gamma=0.5$ to all three paths rather than tuning it per path, and we zero one maximum and one minimum entry per (sample, channel) across tokens rather than whole token rows and columns. Because the published regularization scheme is not replicated exactly, the negative result below bounds our adaptation only; extending it to the method as published would require a replication with the original scheme. Plain MI-FGSM~\cite{dong2018boosting} examples are generated in the same run on the same samples, giving a paired control at an identical budget.

\paragraph{Feature Degradation Metrics}
To analyze how adversarial perturbations affect ViT representations across layers, we compute three metrics at each layer $\ell$. Feature cosine similarity measures directional preservation of the representation:
\begin{equation}
    \text{Sim}_\ell = \frac{h_\ell(x) \cdot h_\ell(x_{adv})}{\|h_\ell(x)\| \|h_\ell(x_{adv})\|}
\end{equation}
where $h_\ell$ denotes the representation at layer $\ell$. Feature norm change captures magnitude effects:
\begin{equation}
    \Delta_\ell = \frac{\|h_\ell(x_{adv})\| - \|h_\ell(x)\|}{\|h_\ell(x)\|} \times 100\%
\end{equation}
Feature $L_2$ distance ($\|h_\ell(x) - h_\ell(x_{adv})\|_2$) quantifies absolute deviation.

\subsection{Statistical Validation}
\label{subsec:statistics}

We separate four sources of variance and report each where it applies. Architecture comparisons turn on training-run variance, so every table reports the mean and standard deviation over three independent runs per architecture (Section~\ref{subsec:training}). Attack-initialization variance is measured by re-running PGD-10 with three attack seeds (42, 123, 456) on a fixed subset; the evaluated samples and their order are fixed, so the seeds vary only the random start of the attack. Protocol variance, the spread across conditioning protocols, is treated as a result and not as noise (Section~\ref{subsec:transfer}). Checkpoint-selection variance, the fourth, comes from the offline rule that picks the final checkpoint from a fixed trajectory (validation split, early-stopping patience, and curve smoothing), measured over eighteen combinations while the trajectory itself is held constant. Section~\ref{subsec:statistics_results} compares their magnitudes.

Paired tests are used wherever the same samples are scored under two conditions: McNemar's exact test for paired binary outcomes, Wilcoxon signed-rank with Holm correction for the three sparsity measures, paired bootstrap confidence intervals (10{,}000 resamples) for differences, and a sign-flip permutation test (20{,}000 permutations) for the both-correct transfer difference. Two units of inference are available throughout and they answer different questions. A per-sample test asks whether two fixed checkpoints differ on the images evaluated; a run-level test, over the three repetitions, asks whether the architectures differ. Only the second supports an architectural claim, and with three runs it is much the weaker. The unit is named next to every test, the run level is used wherever the claim is architectural, and where the two units disagree both are reported instead of the one that favors the claim; Section~\ref{subsec:gradient} is where that happens. Equivalence claims use two one-sided tests (TOST) at a primary margin of $\pm2$ points, fixed before the comparisons from the run-to-run variation in PGD accuracy. That is the right scale for an absolute accuracy and the wrong one for the transfer asymmetry, whose run-to-run standard deviation is $0.23$ points, so there the margin is some eight times too generous and biases TOST toward accepting equivalence. We keep the pre-registered margin instead of retuning it after seeing the data, and report every equivalence claim at $\pm1$ and $\pm3$ points as well; the one equivalence we accept, on SVHN, holds at $\pm1$ too. All evaluation and analysis scripts fix random seeds (seed 42, including CUDA determinism flags), so every reported number will be reproducible from the pipeline we release.
